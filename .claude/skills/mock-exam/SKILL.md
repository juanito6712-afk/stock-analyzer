# 國中模擬試題產生器（雲端版）

## 這套東西怎麼跑

```
使用者在 Claude Code（雲端 session）輸入章節
        ↓
Claude 搜資料 → 出新題 → 寫成考卷 JSON
        ↓
上傳到 Google Drive：模擬試題/考卷/<科目>/
        ↓
更新 模擬試題/考卷索引.json
        ↓
回一個連結：<webAppUrl>?id=<考卷ID>&k=<代碼>
        ↓
孩子/學生用任何瀏覽器作答 → Apps Script 改分 → 成績寫進 模擬試題/作答紀錄
```

**不需要使用者的電腦**。全部靠 Google Drive 連接器 + 一支部署在使用者 Google 帳號下的 Apps Script（原始碼在 `mock-exam/apps-script/`，安裝方式見 `mock-exam/SETUP.md`）。

## 開工前先讀

1. `mock-exam/config.json` — 拿 `webAppUrl`（沒填代表還沒部署，見下面「尚未部署時」）、Drive 根資料夾 ID、預設值。
2. 需要的話用 `mcp__Google_Drive__search_files` 查 Drive。根資料夾 `模擬試題` 底下：
   - `_sources/<科目>/` — 之前搜集的 PDF、整理好的章節重點（PDF 就直接放在科目資料夾裡，
     不必再往下分層；各科底下那個空的 `raw/` 是舊結構，沒在用）
   - `考卷/<科目>/` — 考卷 JSON
   - `考卷索引.json` — 所有考卷的清單
   - `名單.json` — 誰能作答（代碼、姓名、分組）
   - `作答紀錄` — 成績試算表

## 出題流程

### 1. 解析需求

從使用者的一句話抓出：年級學期、科目、章節、題數、難度、指定給誰。沒說的用預設：

| 項目 | 預設 |
|---|---|
| 滿分 | 100 分 |
| 難度 | 段考中等 |
| 給誰 | 八年級 → 宇翔；九年級 → 宇安（`config.json` 的 `gradeOwner`） |
| 題型配比 | 選擇 60%、填充 20%、非選 20%（數理科）；語文科選擇多一點 |
| 難度配比 | 中等 35%、中上 45%、素養 20%（`config.json` 的 `difficultyMix`；2026-10-03 家長調整，原為 50/35/15）；每題在 JSON 裡標 `level`：`中等`／`中上`／`素養` |
| 題數上限 | 50 題（`config.json` 的 `maxQuestions`）；沒特別指定就依範圍多寡抓，範圍小 25–30 題、範圍大接近 50 |
| 作答時間 | 依範圍大小標在 `note`：**小考／小卷**（題數 12 題以上）→ 20 分鐘；**大單元考** → 25-30 分鐘；**段考範圍** → 40-45 分鐘（`config.json` 的 `timeLimits`） |

**課本版本（宇翔，八年級）**——出題一定要照他的版本，考點和課文順序才會對：

| 科目 | 版本 |
|---|---|
| 數學 | 南一 |
| 國文 | 康軒 |
| 英文 | 康軒 |
| 自然（理化） | 南一 |
| 社會（歷史／地理／公民） | 翰林 |

搜資料時把版本一起帶進關鍵字（例如「南一 八上 數學 1-2」），並以該版本的課文範圍為準。

**⚠️ 版本以此表為準，不要用目次檔的出版社標示。** Drive 有一份 `yuxiang_8th_grade_各科目次`（宇翔各科課本目錄），可查章節／課名／頁碼當參考，**但它是 AI 判讀截圖、沒拍到出版社，出版社標示是錯的（國英實際是康軒不是翰林），課名對應也曾出錯**。用它只為了知道「大概有哪些課、順序」，版本一律回到上表；語文科的實際課文、注釋、單字，仍要以康軒課本或老師的講義為準，查不到就照實說明是推估。

**宇安（九年級）**：版本不分（使用者 2026-10-03 指示）；難度可依指示調整（例：練習卷 中等30／中上45／素養25）。素材在使用者 Drive 的共用資料夾「九上社會」（liaok5802@gmail.com 分享，搜尋 `sharedWithMe = true` 找得到）：112 上南一／康軒／翰林「社會3上 C 卷」（平時測驗，地理(五)／歷史(五)／公民(五) 各 9 次；**第一次段考 = 各科單元1～2**，第二次 = 單元3～4，第三次 = 單元5～6）。PDF 是掃描 OCR，圖表會亂掉，只能取題意再自己改編並重驗答案。考卷放 `考卷/社會/`，`subject` 寫「社會」，`assign` 寫 `["宇安"]`。

**九年級歷屆段考題庫（米蘭老師，已整理進 Drive）**：`_sources/113學年度9年級段考試題/`、`_sources/114學年度9年級段考試題/`，底下 `<上|下>學期第N次段考/<社會|自然|全科答案>/`；共 214 個檔案（社會＋自然，題目與答案，來源學校 9 所）。`_sources/九年級/_索引.json` 記錄每個檔案的學年、學期、次別、科目、細項（歷史／地理／公民／理化／地科）、學校、題目或答案、版本、`fileId`，**出九年級題前先讀索引找對應次別的卷子**。注意：
- **九年級下學期只有第 1、2 次段考**（第 3 次太接近會考，學校通常不辦，米蘭也沒有）；九上才有第 1～3 次。
- 九上第一次段考範圍＝社會 地理／歷史／公民 各單元 1～2、自然 第 1～2 章（見上）。
- 檔名寫法很多，以索引為準；有些檔 `school` 是「未標示學校」（不影響使用）。
- 這些是別校的考卷，只能「改編」不能整份照抄（見「找素材」原則）。

**九上自然（宇安）**：同一位共用者另有資料夾「校用大卷」（`sharedWithMe = true` 可搜到），內有 康軒／翰林／南一「自然3上」A／B／C 卷（110 及 112 上），九年級自然(五) 共約 11～16 次平時考。**第一次段考 = 第1～2章（直線運動、力與運動），約在第 1～5 次平時考**；第 3 章起（功與機械應用或功與能、電）屬第二次段考以後。力矩在翰林／康軒屬第 2 章、南一屬第 3 章，不分版本時只放少量。考卷放 `考卷/理化/`，`subject` 寫「理化」，`assign` 寫 `["宇安"]`。

### 2. 找素材

**出題原則（家長 2026-10-03 指示）：盡量以雲端硬碟 `_sources/` 內各校現有的題目去「改編」**（換數字、換情境、改選項、調整難度），不要整題照抄，也不要憑空出。改編時：
- 先查 `_sources/課程進度.md` 與題目所屬的學期／章節，**確認進度相符**（範圍外的題目不用；例如卷子是上學期後半、而宇翔還沒教到，就不改編）。
- 改編題的難度要重新判斷並標對 `level`，整份卷子照 35/45/20 配比。
- `sources` 欄位寫明改編自哪份卷子（校名、學年度、第幾次段考）；`_sources/` 沒有對得上的題目才上網搜，仍找不到才自己依課綱出，並在 `note` 說明。
- 答案與解析要自己重算／重驗過，不要沿用來源的答案不檢查（來源卷也會有錯）。

先看 `_sources/<科目>/` 有沒有這個章節的舊資料——**有就直接用，不要重搜**。

科目資料夾的對應要注意合科卷：

| 使用者說的科目 | 除了同名資料夾，還要看 |
|---|---|
| 歷史 / 地理 / 公民 | `_sources/社會/`（三科合印的段考卷，檔名多半寫「社會」） |
| 理化 | `_sources/理化/` 裡檔名寫「自然」的（八年級自然科就是理化） |
| 生物 / 地科 | 目前是空的（孩子在八年級，自然只考理化），要先上網搜 |

檔名裡的 `114-1-2` 是「學年度-學期-第幾次段考」，`8` 或「二年級」是八年級。
挑素材時優先用同一學期、同一次段考的卷子，範圍才會對得上。

沒有的話上網搜（WebSearch / WebFetch）：

- 各校段考卷 PDF：搜「<章節> 段考 試題 filetype:pdf」「<年級><科目> 第一次段考 <章節>」
- 教育部 / 教育雲 / 學習吧 的教材與練習題
- 會考歷屆試題（相關考點）
- 米蘭老師題庫 <https://melances.com/test-bank/>（自然科）
- 中小學題庫網 <https://www.tcool.cc/>

**已知限制：tcool.cc 的考卷抓不下來**（動態載入），只能當搜尋範圍之一。

搜到有用的東西就整理成一份 `<章節>-重點.md` 存進 `_sources/<科目>/`，下次直接用。

### 3. 出題

- **事實要交叉查證，不能只信一則搜尋摘要。** 作者、出處、人名、年代、課文主旨與寫作手法這類「會直接變成標準答案」的事實，至少要有兩個獨立來源互相印證才寫進題目。WebSearch 的摘要是 AI 整理的，會張冠李戴（實例：〈土芭樂的生存之道〉作者其實是劉克襄，摘要卻說洪醒夫；又把這篇寫成「托物說理的人生啟示」，查無依據）。查不到全文時，只出「已證實的內容」，並在 `note` 寫明哪些部分是推估；**不要為了湊題數自行發揮主旨或寫作手法**。
- **不照抄**。參考題型、難度、常見陷阱，重新出題。
- **每題的答案自己算過一遍**，特別是計算題。填充題的 `answer` 要把等價寫法都列進去（`6x` 和 `+6x`）。
- 錯誤選項要是「真的會錯的地方」（忘記乘 2、漏掉負號、平方差與完全平方混用）。
- `explain` 寫解題關鍵，不是只寫答案，並點出這題常見的錯法。
- 數學式用 `\\(` `\\)` 包起來（MathJax），換行用 `<br>`。
- 如果這個學生在同章節錯過題（見「錯題分析」），在錯過的觀念上多出 1–2 題。

#### 圖表題目標與工具（使用者 2026-10 要求提高圖表題比例）

- **目標**：含圖或表的題目占 **15～30%，依科目與範圍決定**（使用者 2026-10-04 調整，原先的 25～35% 太高）。理化、數學、地理的圖表自然多，取 25～30% 上下；歷史、公民取 15～20%（史料、表格、情境圖）；語文、英文以閱讀短文／表格／告示為主，不強求 SVG。範圍本身不適合畫圖（例如純背誦的單字卷、默寫卷）就不要硬湊。
- **工具**：`mock-exam/tools/figures.py`（折線／v-t／x-t 圖、直條圖、雨溫圖、圓餅圖、數線、打點紙帶、串聯電路、受力圖）產生 SVG；`mock-exam/tools/render_check.js <考卷.json> <資料夾>` 把每個含圖的題目截成 PNG，**上傳前一定要看過圖**。新的圖型先加進 figures.py 再用，讓之後可重複使用。
- **圖與答案要同源**：圖的數據、題目、答案、解析由同一組變數產生（腳本內算，不要手算後再畫），避免圖與答案不一致。
- **做不到的**：真實地圖、照片、標本圖、實驗裝置照片無法精準重現；只能用示意圖，且 `note` 要註明「圖為示意」，或改成文字描述題，不要硬畫不準的地圖。
- **來源卷的圖**：PDF 掃描檔的圖表 OCR 會亂掉；用 `pdftoppm` 把頁面轉成 PNG 看圖，再用 figures.py 重畫（改數據），不直接沿用原圖。

#### 圖形題（SVG）

`q` 欄位是直接以 innerHTML 塞進網頁的，所以**可以在題目裡內嵌 SVG**，做出參考書、段考卷常見的圖形題。這是純文字題之外的加分項，數理與地理尤其該多用。

- 適合用 SVG 畫的：幾何圖（角度、三角形、平行線、面積）、座標平面與函數圖、統計圖（長條圖、圓餅圖、折線圖）、地理示意圖（三級階梯剖面、經緯度、等高線）、理化圖（電路、力圖、光路、實驗裝置）。
- **配色要跟深淺色主題相容**：線條與文字用 `stroke="currentColor"` `fill="currentColor"`，需要區別的顏色才另外指定（挑深淺底都看得清的顏色，例如 `#2f6f5e`、`#c0392b`）。不要用純黑填滿，深色主題會看不到。
- 加 `width`／`height` 或 `viewBox` 讓它在手機上不會爆版，寬度建議 ≤ 320。字級用 `font-size` 標清楚。
- 選項若是「看圖判斷」，就把圖畫在題幹 `q` 裡，選項照常放文字。
- **做不到的**：真實照片、實景圖、地圖實圖——這些沒有圖庫可用，不要假裝畫得出來；改用示意圖或純文字描述情境。
- 範例（一個標了角度的三角形）：
  `"q": "如圖，三角形 ABC 中，∠A=40°、∠B=60°，求 ∠C。<br><svg viewBox=\"0 0 200 120\" width=\"200\" xmlns=\"http://www.w3.org/2000/svg\"><polygon points=\"20,100 180,100 60,20\" fill=\"none\" stroke=\"currentColor\" stroke-width=\"2\"/><text x=\"58\" y=\"18\" font-size=\"12\" fill=\"currentColor\">A</text><text x=\"12\" y=\"112\" font-size=\"12\" fill=\"currentColor\">B</text><text x=\"182\" y=\"112\" font-size=\"12\" fill=\"currentColor\">C</text></svg>"`

### 4. 寫成考卷 JSON

檔名 `<YYYYMMDD>-<章節>.json`，格式：

```json
{
  "id": "20260919-math8a-multiplication-formulas",
  "title": "乘法公式練習卷",
  "grade": "八年級上學期",
  "subject": "數學",
  "chapter": "乘法公式",
  "note": "給宇翔｜建議作答 40 分鐘",
  "assign": ["宇翔"],
  "sources": [{ "name": "…", "url": "…" }],
  "sections": [
    {
      "type": "mc", "name": "選擇題", "points": 5,
      "questions": [
        { "q": "\\((x+3)^2\\) 展開後等於？", "options": ["…","…","…","…"], "answer": 2, "explain": "…" }
      ]
    },
    {
      "type": "fill", "name": "填充題", "points": 4,
      "questions": [{ "q": "…＿＿＿＿", "answer": ["6x", "+6x"], "explain": "…" }]
    },
    {
      "type": "open", "name": "非選擇題", "points": 10,
      "questions": [{ "q": "…", "answer": "參考答案（可用 <br>）", "explain": "配分說明" }]
    }
  ]
}
```

- `type` 只有 `mc`（選擇，`answer` 是選項索引 0–3）、`fill`（填充，`answer` 是可接受答案陣列）、`open`（非選，交卷後孩子自評）。
- `points` 是**每題**分數，滿分 = Σ(points × 題數)，湊到 100。
- `assign`：可填姓名或 `名單.json` 的 `group`。不寫 = 所有人都看得到，家教學生也會看到——**給孩子的卷子記得寫**。

### 5. 上傳 Drive

**先在本機把 JSON 寫成檔案（放 scratchpad），跑檢查通過再上傳**：

```bash
node mock-exam/test/validate_exam.js <考卷.json>
```

它會擋下 JSON 語法錯誤（手寫的 JSON 一個逗號錯，孩子就整份打不開）、選擇題答案索引超出範圍、填充題沒答案、SVG 標籤沒成對，並警告滿分不是 100（實例：理化卷我報「100 分」，實際只有 97）與難度比例偏離 35/45/20。**回報給使用者的題數、滿分，以檢查腳本印出的數字為準，不要憑印象。** 上傳後用 `wc -c` 對照 Drive 回傳的 `fileSize`，確認傳的是驗證過的那份。

用 `mcp__Google_Drive__create_file`（`parentId` = `考卷/<科目>/` 資料夾 ID，`contentMimeType: "application/json"`，`disableConversionToGoogleType: true`）。科目資料夾不存在就先建一個（`mimeType: application/vnd.google-apps.folder`）。

**記下回傳的 file id**，下一步要用。

### 6. 更新考卷索引

讀 `考卷索引.json`，把新的一筆加進陣列：

```json
{
  "id": "20260919-math8a-multiplication-formulas",
  "date": "2026-09-19",
  "subject": "數學",
  "grade": "八上",
  "chapter": "乘法公式",
  "title": "乘法公式練習卷",
  "file": "考卷/數學/20260919-乘法公式.json",
  "fileId": "<create_file 回傳的 id>",
  "assign": ["宇翔"]
}
```

⚠️ **Drive 連接器不能覆寫既有檔案內容**（`update_file` 只改標題和位置）。更新索引的做法是：`create_file` 寫一份新的 `考卷索引.json` 到同一個資料夾 → `trash_file` 把舊的丟進垃圾桶。順序不要反，中間壞掉的話至少舊的還在。

索引壞掉也不會全毀：Apps Script 讀不到索引時會自己掃 `考卷/*/*.json`，只是就沒有 `assign` 和標題了。

### 7. 回覆使用者

給出：

- 作答連結 `<webAppUrl>?id=<考卷ID>&k=<代碼>`（代碼去 `名單.json` 對 `assign` 的人拿；要給多個人就一人一條）
- 題數配比與滿分
- 參考來源；**如果某個來源連結失效或抓不到，要講出來**，不要假裝有參考
- 哪幾題是針對他之前錯的觀念加強的

### 尚未部署時

## 每日聯絡簿自動出題（週一到週五 16:00 台灣時間的排程）

有一個 Routine 每個上學日下午 4 點自動觸發，任務是：讀宇翔的聯絡簿 → 找出「隔天」要考的科目與範圍 → 各出一份模擬卷。手動被要求「看聯絡簿出隔天的考試」時也照這個流程。

1. **讀聯絡簿**：`config.json` 的 `contactBook.宇翔.docId`，用 `mcp__Google_Drive__read_file_content` 讀。
2. **定位今天**：聯絡簿每天一個日期標題（如 `09/21(一)`），底下表格右欄是「考試」。找出**今天日期**那一格。找不到今天就找最近一筆，並在回報時說明。
3. **抓「明」開頭的考試**：考試欄裡以「明」開頭的就是隔天要考的。解析出科目 + 範圍。

   **⚠️ 查出範圍後，一定要對照 `_sources/課程進度.md`（家長提供的正確章節表）確認那一課的完整內容。** 有些「一課含多首詩／多篇」，聯絡簿只寫「L2」不會告訴你，漏了就會少考。例：國文 **L2 是「古體詩選」，含兩首：庭中有奇樹＋慈烏夜啼**，兩首都要考；L3 是「土芭樂的生存之道」。不要只憑聯絡簿的簡稱就出，先查課程進度表。

   科目簡稱對照：

   | 簡稱 | 科目 | 版本 |
   |---|---|---|
   | 國 | 國文 | 康軒 |
   | 英 | 英文（英單／英課） | 康軒 |
   | 數 | 數學 | 南一 |
   | 理 / 自 | 理化（自然） | 南一 |
   | 地 | 地理 | 翰林 |
   | 史 | 歷史 | 翰林 |
   | 公 | 公民 | 翰林 |

   範例：「明數課考數 1-2」→ 數學（南一）1-2 章；「明英課考英單 L2 22-42」→ 英文（康軒）L2 單字 22-42；「明國課考 L3 注釋 2~8」→ 國文（康軒）L3 注釋。同一天可能好幾科，每科各出一份。
   **英單（2000單）的範圍以家長提供的字表為準，不要自己從單字書推。** 目前字表：
   - U26 動物：sheep、snake、spider、swan、tiger、turkey、turtle、whale、zebra（另有易混字 snail、swallow、tail；wolf、worm 為推測，沒確認就不要當主角出題）。
   - U27 冠詞與限定詞：a、an、the、this、that、these、those、my、your、his、her、its、our、their。
   - 家長註：優先掌握這 23～24 個共同單字，涵蓋超過九成的考題核心範圍。出題以字表為主；沒有字表的 Unit，先請家長提供，或在回報裡標明「依推估」。

4. **逐科出題**：照上面「出題流程」走，用該科版本、難度配比（中等35／中上45／素養20）、題數依範圍抓（≤50；小考／小卷範圍窄就 20–30 題）。`assign` 標 `["宇翔"]`，`note` 註明「隔天考試模擬｜<科目><範圍>」。
5. **上傳、更新索引**：同「出題流程」5–6。
6. **回報**：把每一科的作答連結（帶 `k=yx-2026`）整理成一則訊息。排程是無人看守的新 session，所以要靠通知推播給家長，訊息裡列出：日期、隔天考哪幾科、每科連結、題數、參考來源、有沒有哪一科資料不足只能靠課綱推估。

**工作量大時可分派子代理**（大白／小白／小馬）：可以一科一個子代理平行出題，最後彙整連結一起回報。
